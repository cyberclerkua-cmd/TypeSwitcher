# Многоязычное ядро TypeSwitcher

## Контекст языка

`LanguageProfile` задаёт алфавит, идентификатор, Windows LANGID, нормализацию и масштаб
частот. UK обозначается `uk` / `uk_UA`, LANGID `0x0422`. Интерфейс обработки работает
через `LayoutTarget.En/Ru/Uk`; прежние численные значения En/Ru сохранены.

`InputProcessor` передаёт в `Analyzer.Analyze` язык активного окна. Самостоятельный
вызов без контекста использует эвристику по алфавиту; в CLI источник можно указать
параметром `--language`. Неподдерживаемый HKL в живом вводе сбрасывает состояние.

Автоматическая смена требует валидности в целевом словаре и невалидности в исходном.
Два допустимых целевых языка дают `ambiguous-layout`; сырые сегменты подчиняются той
же политике. Баллы разных языковых моделей напрямую не сравниваются. Для опечаток
текущего языка сохраняются расстояние редактирования и gap лучшего кандидата.

Частотные кандидаты проходят морфологическую проверку: UK-корпус содержит некоторое
количество русских слов, и частота сама по себе не должна разрешать их как UK-замену.
Для небольшого UK-корпуса логарифм частоты сглаживается масштабом 50: редкая словоформа
не подавляет альтернативное окончание только из-за нескольких наблюдений.

## Физический ввод и откат

Сегмент содержит vk, scan, Shift, Caps Lock и AltGr. Перевод выполняется через
`ToUnicodeEx` с явно заданным состоянием. Непереводимая клавиша отменяет гипотезу
целиком. Украинский Right Alt допускается для печатных клавиш; Ctrl/Alt/Win-команды
проверяются до хоткеев. Поля паролей проверяются также перед окном слова.

Откат хранит исходный и целевой HKL целиком, а также исходный разделитель. Поэтому
возвращается конкретный вариант раскладки, а `/`, преобразованный в `.`, восстанавливается
как `/`. Ручной переход следует `languages.order`, пропуская выключенные/отсутствующие языки.
Одинаковый вид слова в RU/UK не мешает переключению самого HKL.

Апострофы `'`, `’`, `ʼ` внутри украинского/английского слова копятся в буквенном буфере.
Поиск использует NFC и единый апостроф; при исправлении сохраняется стиль апострофа.
Комбинируемые знаки не перенабираются из-за различий удаления графем в приложениях.

## Словарные снимки

`DictionaryManager.Load` создаёт новый `Dictionaries`: основные Hunspell, дополнения,
частоты, пользовательские списки, модели и индексы по каждому включённому языку.
Прогрев Hunspell/JIT проходит до установки хуков или публикации снимка.

При сохранении настроек App выполняет загрузку в фоне, последовательно через gate.
Предыдущее поколение отменяется. Конфигурация и словари переключаются на потоке хуков
вместе со сбросом состояния набора. Ошибка загрузки не заменяет работающий набор.
Пользовательские списки подменяются одной ссылкой на неизменяемый снимок.

Запросы Hunspell имеют кооперативные ограничения времени. Общий поиск кандидатов
имеет бюджет 100 мс; исчерпание возвращает пустой результат, а не частичный «единственный»
кандидат. Это ограничение отдельного поиска, не гарантированная верхняя граница всей
обработки: UI Automation и планировщик Windows проверяются отдельно на стенде.

Кеш n-gram имеет версию 3 и включает язык, режим обучения, SHA256 и штамп источника.
Для импортированных частот модель строится по объединённым частотам в памяти.

## Импорт

Пакет описывает `AppConfig.DictionaryEntry`: GUID, язык, вид, относительные пути,
SHA256, число строк и дату импорта. Набор проходит ограниченное копирование, проверку
UTF-8/формата, загрузку Hunspell во временной директории и атомарное переименование.
Конфигурация сохраняется после успешного импорта. Отмена и ошибка удаляют staging.

Файлы находятся в `data/imported/<guid>/`. Пути за пределами собственного каталога
и ссылки-каталоги отклоняются. При следующей загрузке сверяются контрольные суммы.
Обновление создаёт новый набор; прежний рабочий снимок читает уже загруженные данные.

## Пользовательские списки и миграция

Схема config.json — 2, резервная копия схемы 1 — `config.json.v1.bak`.
Общие `my_words.txt`, `stopwords.txt`, `rules.txt` сохраняют свои пути и приоритеты.
Языковые варианты имеют суффикс `.ru`, `.en`, `.uk` перед `.txt`.

Приоритет: стоп-слова → общие правила → языковые правила → личные слова → автоматический
анализ. Общий my_words исторически расширял RU-валидность и защищал ввод во всех языках;
для UK-валидности используются явные UK-списки. Чужая будущая схема не перезаписывается
на старте. Текстовые списки и JSON записываются через временный файл и переименование.
